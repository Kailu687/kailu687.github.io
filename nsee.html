NSEE - Neuro-Symbolic Edge Agent

Experimental software project

PythonNeuro-symbolic AISpiking neuronsRF designOpen source

Overview

NSEE (Neuro-Symbolic Edge Agent) is an experiment in building an assistant without a large language model. Instead of one big neural network, a small rule-based program reads the request, picks a skill, checks it and runs it, all offline on a laptop and in under 1 MB of standard-library Python.

I wanted to see how far this approach can go, so I measured both what it does well and where it fails, and published the code, the raw results and a list of limitations.

How it works

  • Intent compiler : turns a request into goals and keeps negation scoped, so "sort my files, don't delete anything" becomes sort = allowed, delete = blocked.
  • Skill capsules : each skill is a JSON file with parameters, formulas and rules, not code. New abilities are added as data.
  • Spiking-neuron circuits : small leaky integrate-and-fire circuits take part in routing and in learning which skill works for which request.
  • Safety and rollback : every file operation needs approval, is previewed first and is journaled, so a failed multi-step task is undone completely.

RF antenna skill

One capsule designs six antenna types (microstrip patch, dipole, monopole, axial-mode helix, Yagi-Uda and pyramidal horn) from standard closed-form formulas, and writes an Ansys HFSS (PyAEDT) script. It understands casual input such as "patch 5.8G" or "desing a dipole at 433 mhz". The scripts pass a syntax check; running them in HFSS is my next step.

What I worked on

  • Set the goals and constraints: offline, standard library only, under 1 MB, skills as data.

  • Directed the implementation, which was built with heavy help from AI coding assistants, and reviewed and tested the behaviour.

  • Designed and ran the experiments: held-out test sets, a keyword baseline, a rollback fault-injection test and a comparison of the spiking arbiter against simpler methods.

  • Wrote up the results, including the parts that did not work.

Outcome & Learning

Small symbolic systems turned out to be fast, predictable and safe for well-defined procedures, but weak at natural phrasing and open-ended language. One honest surprise: the spiking arbiter made the same decisions as plain thresholding on all 60 test cases, so it does not improve routing yet.

The biggest lesson for me was to measure the thing I want to claim, and to report the failures as clearly as the successes. I am still learning many of the ideas underneath this project.
